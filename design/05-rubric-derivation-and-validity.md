# Design — Rubric 도출 이론 & 타당도(왜 이 기준인가)

> 목적: "왜 하필 이 축들?"에 "이것 말고는 될 수 없다"로 답하는 1차 원리 도출 + 채점을 신뢰할 수 있는 근거(construct validity). 제품 신뢰의 핵심 자산. (전면 노출용 — 권위가 아니라 *반증 가능한 공개 가설*로 제시.)

## 1. 구성(construct)의 경제학적 정의
"AI를 많이 쓴다"가 아니라 *경제적* 정의: **내 희소 자원(시간·노력) 단위당 가치를 더 뽑는가, 그 우위가 지속되는가.** 어떤 우위든 3성분으로 분해됨:

> **우위 = 크기(Leverage) × 부호(Trust) × 지속성(Compounding)**
- **Leverage** = 내 노력 대비 산출의 크기.
- **Trust** = 그 산출의 부호. 틀린 산출은 가치를 깎으므로(음수) 레버리지는 신뢰로 *곱*해져야 함.
- **Compounding** = 시간 지속성. 1회성 부스트는 우위가 아님(즉시 따라잡힘). 누적돼야 해자.

→ 이 셋은 임의가 아니라 *모든 경제적 우위 분석에 필요한 3성분(크기·방향·지속성)*. 그래서 빠질 수 없음.

## 2. 축 = 3성분 × "AI와 일하는 제어 루프"
AI 시대 사람의 일 = *비결정적·빠르고·싸고·틀리고·맥락에 갇힌 에이전트를 지시·검증*. 루프 각 단계에서 크기·부호·지속성을 결정하는 능력이 곧 축:

| 루프 단계 | 결정하는 것 | 축 | 성분 |
|---|---|---|---|
| 무엇을 어느 고도로 위임 | 레버리지 천장 | **D1 위임 고도** | Leverage |
| 무엇을 컨텍스트로 | 입력 측 품질 | **D3 컨텍스트** | Leverage |
| 실행 루프를 얼마나 자율로 | 실행 측 레버리지 | **D4 오케스트레이션** | Leverage |
| 얼마나 싸게 반복·수렴 | 시간당 레버리지 배수 | **D6 반복·폐기** | Leverage |
| 틀릴 곳에 검증 배치 | 산출의 부호 | **D2 검증** | Trust |
| 모델 약점 우회·라우팅 | 위임의 성공 | **D5 한계 운전** | Trust |
| 1회성→재사용 자산화 | 이득의 지속성 | **D7 복리화** | Compounding |

= **4 레버리지 + 2 신뢰 + 1 복리 = 7.** (3성분) × (루프 단계)의 산물.

## 3. 연결 법칙 (왜 단순 평균이 아닌가)
> **가치 = 레버리지 × 신뢰**, **해자 = (레버리지 × 신뢰)를 시간 적분(복리).** 곱셈 구조.
- 신뢰 없는 레버리지 = 빠르게 틀린 것 양산(음수) → scoring에 곱셈 게이트 `D1_adj = D1 × (0.5+0.5·D2/100)`. "함정형" 프로파일.
- 레버리지 없는 신뢰 = 느리고 꼼꼼(native 아님).
- moat **3-게이트 = 3성분 각각 시험**: G1 신뢰(D2·D3) ∧ G3 레버리지 비취약 ∧ G2 복리(D7). 임의 임계치 아님.
- **보이는 것(레버리지=모방 쉬움) vs 안 보이는 것(신뢰·복리=내구적)** → 가중치를 D2·D3·D7에. 해자는 따라잡기 어려운 데 있으니까.

## 4. 완전성·비중복 (반증 가능한 주장)
- **완전성**: 누가 어떤 "AI 스킬"을 대도 7축의 하위 사례로 환원돼야 함("프롬프트 잘 씀"=D3+D1, "어느 모델"=D5, "CLAUDE.md"=D7+D3). **환원 안 되는 게 나오면 rubric 불완전 = 반증.** (공개해두면 "근거 없이 정함"이 아니라 반증 가능한 분류 주장이 됨.)
- **비중복**: 각 축이 루프 한 단계 소유. 겹침은 배정 규칙(D1=요청 고도, D4=실행 자율성 — 교차검증).
- **consume vs build**: 별도 축 아니라 *복리 성분이 모든 축의 L4에서 발현*.

## 5. 척도(L0–L4) 단일 생성 원리
> 모든 축 공통 사다리 = **체계화된 자율성↑ + 인간 역할의 추상화 고도↑** (Ericsson AI-native 원리의 개인판).
- L0 AI부재 → L1 최저grain 보조(consume) → L2 단위작업·매번 사람 트리거 → L3 다단계 자율·사람 감독 → **L4 시스템에 박음(룰·훅·자산 기본값화·자가개선 = build).**
- 모든 축 L4 = "네 시스템에 빌드". 척도가 축마다 임의 아닌 같은 원리의 투영 → 0–100 축 간 비교 가능 + "왜 L4=build"가 자동 설명.
- 레벨은 선형 good 아니라 *신뢰 조건부 good*(§3 곱셈과 일관).

## 6. 타당도 사다리 — 지금 어디, 어떻게 올라가나
| 단계 | 종류 | 상태 |
|---|---|---|
| 1 face (그럴듯) | ✅ |
| 2 content (구성 정의·근거) | ✅ §1·2·4 |
| 3 reliability (같은 입력→같은 점수) | 결정적 메트릭 ✅ / LLM-judge는 신뢰구간 표시 |
| 4 **criterion/predictive** (점수가 실제 성과 예측?) | ❌ 코호트 N 필요 ← 진짜 신뢰는 여기 |
| 5 convergent (전문가·known-answer 일치) | ❌ 테스트셋 구축 예정 |

→ 4·5 전까지 **"점수=가설" 라벨.** 정직함이 신뢰를 삼.

## 7. 지금 신뢰 가능하게 파는 법 (전면 원칙)
1. **관찰 사실 기반 진단+처방 1순위** (전역 구성 검증과 무관하게 거의 항상 참). 카디널 점수·moat 판정은 *방향성 가설*로 2순위·라벨링.
2. ★ **자기검증 가능성**: 인용된 인스턴스를 본인 기억과 대조 가능 = 반증 가능 = 대부분 assessment에 없는 신뢰 원천.
3. **rubric을 권위 아닌 공개·버전관리·증거갱신 오픈 아티팩트로.** 없는 권위 가장 X.
4. **glass box 강제**: 모든 점수가 인용 근거로 분해 안 되면 출시 X.
