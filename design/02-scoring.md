# Design — Scoring 모델

핵심 원칙: **설문 자기보고 0%, 관찰 증거 100%.** 사용자가 "잘 쓴다"고 말하는 게 아니라 transcript/git/tool-call이 증명하거나 반증한다.
> ⚠️ 이 산출물은 자체적으로 6축으로 작성됨. 통합 brief는 rubric 7축을 정본으로 채택했고, 아래 축 번호는 본 산출물 내부 기준(brief §0에서 매핑 정리). moat 게이트·가중치의 *논리*가 핵심.

## 1. 시그널 → 점수 매핑 (예시 축 D1·D2)

### D1 Delegation Depth
| 증거(source) | L0 | L2 | L4 |
|---|---|---|---|
| 세션당 turn 수 / 작업당 tool-call 수 | 1-2 단답 | 5-10, 단일 도구 | 15+ 자율 루프, 다중 체인 |
| 위임 추상화 | "이 단어 뜻?" | "이 함수 고쳐" | "이 디렉토리 분석해 X 산출" |
| Agentic 비율 = 자율 turn/전체 | <10% | 30-50% | >70% |

### D2 Verification Rigor
| 증거 | L0 | L2 | L4 |
|---|---|---|---|
| 검증 행동 빈도(실행·테스트·교차질문·반례) | 바로 채택 | 가끔 "맞아?" | 출력마다 실행/테스트/대조 |
| 검증 방법 종류 수 | 0 | 1(눈으로) | 3+ (실행·테스트·외부 cross) |
| 틀린 출력 catch율 | 통과 | 일부 | 대부분+정정 요구 |
| 출처 요구율 | ~0% | 10-30% | >40% |

(D3 Iteration·D4 Context·D5 Orchestration·D6 Compounding도 동형 매핑 — 각 행 점수의 축 내 평균이 축 점수, L0=0-20·L2=40-60·L4=80-100, L1/L3 보간.)

## 2. 종합 점수 & 가중치
단순 평균 **아님**. native 본질 = "신뢰 보정된 레버리지". 보이지 않는 축에 가중:

| Dim | 가중 | 근거 |
|---|---|---|
| D2 Verification | 0.22 | 검증 없는 위임=위험 증폭. 핵심 분별력 |
| D4 Context Eng | 0.20 | 입력 설계가 출력 품질 지배 |
| D6 Compounding | 0.18 | moat의 시간축 |
| D1 Delegation | 0.15 | 필요조건이나 단독으론 native 아님 |
| D3 Iteration | 0.13 | 숙련 신호이나 D2·D4와 상관 높음 |
| D5 Orchestration | 0.12 | 강력하나 도구 트렌드 의존, 모방 쉬움 |

**종합 점수보다 프로파일(모양)이 중요**: 균형형(60-70 고름, 첨예 해자 없음) / 첨탑형(D2·D4 90, D5·D1 40 = 모방 어려움, **더 가치**) / 함정형(D1·D5 90, D2 30 = false-positive). 분류 = 축 벡터의 분산+최저축 위치.

## 3. ★ Moat Threshold (3-게이트 AND)
| 게이트 | 조건 | 이유 |
|---|---|---|
| G1 분별력 | D2≥70 AND D4(컨텍스트)≥70 | 모방 가장 어렵고 도구 무관 |
| G2 복리 | D6≥65 | 축적돼야 시간이 갈수록 격차 확대 |
| G3 비취약성 | 최저축≥45 AND D5(오케스트레이션) 비중 상단 아님 | 단일 도구 트렌드 비의존 |

판정: **MOAT**(G1∧G2∧G3, ≈72+) / **EMERGING**(G1 충족·G2 미달, 처방 즉효) / **COMMODITY**(D5·D1만 높음 — 도구 바뀌면 리셋) / **NOVICE**(다수<40).

> 핵심 주장: **D5(도구)·D1(위임량)은 가시적이나 해자가 아니다.** 누구나 도달. 해자는 *안 보이는* 검증·컨텍스트·복리. 게이트 무게가 여기.

## 4. 개인화 처방 로직
보편 조언 금지. *그 사람 실제 행동 데이터의 anchor*에 묶음.
```
1. 최저 2축 선정 (moat 게이트 막는 축 우선)
2. 어떤 시그널 행이 점수를 끌어내렸는지 특정
3. 사용자 로그에서 그 행동 인스턴스 3개 인용(날짜·파일·발췌)
4. "이렇게 했어야"로 재작성
5. 다음 7일 측정 가능 행동 1개 + 재측정 시점
```
각 처방 **(현재 행동 인용 → 구체 대체 행동 → 측정 지표 → 재측정일)** 4요소 필수.

## 5. False-Positive / False-Negative
| 유형 | 증상 | 처리 |
|---|---|---|
| FP-1 많이 쓰나 native 아님 | 위임량↑ + D2<35 | `D1_adj = D1×(0.5+0.5·D2/100)` 페널티 + COMMODITY 강제 |
| FP-2 화려한 도구 쇼 | D5↑ + D6↓ | G3에서 차단(설계됨) |
| FN-1 적게 쓰나 native | D1·D5↓ but D2·D4·D6↑ | 강등 금지. "효율형 native" 플래그 |
| FN-2 침묵 검증 | 검증을 머릿속/외부에서 → transcript에 없음 | git·외부 산출물 cross-source 보정. transcript 단일 의존 금지 |

**안전장치**: 가시적 활동량(D1·D5)은 *증거 아닌 정황*. 무게는 항상 D2·D4·D6. "많이 쓴다 ≠ native"를 모델 구조에 인코딩.

## 6. 예시 — Patient-Zero 진단 (익명·가정 추정)
프리랜서 AI 컨설턴트. Claude Code로 멀티위크 분석을 1인 운영. git = 단계별 노트+산출물, 상호참조 메모리. (식별 정보 제거 — 방법론 시연용 합성 예시.)

| 축 | 점수 | 근거 |
|---|---|---|
| D1 | 72 | 멀티위크 분석을 멀티파일 산출로 위임 |
| D2 | 58 | 출처/추론 분리 규칙=검증 의식. 단 실행·반례 루틴 불균일 → G1 차단 |
| D3 Iteration | 70 | 사실 정정 커밋들=진단적 수정·학습 |
| D4 Context | 80 | 계층적 메모리 인덱스+상호참조+포맷 규칙 |
| D5 Orch | 55 | git+노트+메모리 결합. 자동화·병렬·MCP 약함 |
| D6 Compound | 78 | 단계별 누적+인덱싱 메모리+산출 파생 |

종합 ≈ **69.3**. 프로파일 = **첨탑형(설계자형)** — D4·D6 첨탑, D2·D5 골.
Moat 판정: G1 D2(58)<70 **차단** ❌ / G2 D6(78)≥65 ✅ / G3 최저 D5(55)≥45 ✅ → **EMERGING**. 자산화·맥락설계는 해자급, *검증 루틴이 transcript에 안 남아* G1 미달 + FN-2 위험 동시.

처방(D2 우선): 분석 노트 말미에 `## 반증 시도` 강제 — "이 결론이 틀렸다면 어떤 데이터가 보여줄까/누가 반대 증거를 쥐나" 2줄. 측정: 반증섹션 보유율 0→100%, 7일 후 D2 재산출(목표 58→72, G1 통과→MOAT 승격).
**FN-2 보정**: 컨설턴트는 검증을 외부 미팅·현장 대조로 수행 가능성↑ → 외부 산출물 cross-source를 D2 증거로 반드시 합산.
