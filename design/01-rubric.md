# Design — 역량 Rubric (정본 7축)

설계 원칙: 모든 시그널은 **transcript / git log / 파일시스템 / 설정파일에 남는 흔적**으로 측정 가능해야 한다. "그렇게 한다고 응답"이 아니라 "그렇게 한 흔적"만 채점. 측정 불가(태도·학습의지)는 버리고, 흔적이 겹치는 것은 통합·재정의했다. 7개로 확정.

## D1. 위임 고도 (Delegation Altitude)
**정의** — AI에게 넘기는 작업 단위의 추상화 수준. 토큰 단위 자동완성 vs 목표 단위 임무 위임.
**가르는 행동** — 가끔 쓰는 사람은 *자기가 이미 답을 아는* 좁은 조각을 시킴. native는 결과 명세+제약만 주고 경로 탐색을 위임하되 검증 가능한 형태로 받음.

| L | 시그널 |
|---|---|
| 0 | 단발 Q&A. 한 턴=한 질문. 복붙, 후속 없음 |
| 1 | 좁은 조각("이 정규식 고쳐줘"). 프롬프트가 이미 해법 묘사, AI는 받아쓰기 |
| 2 | 함수·파일 단위. 멀티턴이나 매 스텝 사람이 지시(micro-step) |
| 3 | 목표+제약+검증기준 한 번에, 다단계 실행 위임. tool-call 체인 3+ 스텝 무개입 |
| 4 | 임무 단위 + 자기검증 루프 내장. 사람은 게이트 결과만 검수. "성공조건/실패시 행동" 사전 정의 |

**자기기만** — "큰 일 맡긴다"지만 transcript상 매 턴 마이크로 지시. *고도* 아닌 *분량*을 위임으로 착각.

## D2. 검증·불신 설계 (Verification & Calibrated Distrust)
**정의** — 믿을지 말지를 *구조적으로* 결정. 검증 존재 여부가 아니라 **틀릴 곳에 선택적으로** 배치하는가.
**가르는 행동** — 아마추어는 0 아니면 100. native는 hallucination 위험·비용에 비례해 검증 강도 조절.

| L | 시그널 |
|---|---|
| 0 | 검증 흔적 없음. 그대로 커밋/다음 단계 |
| 1 | 사후 수동 검증만(중복노동). 검증이 AI 밖에 |
| 2 | 실행 기반 검증 도입(코드 돌려봄). 단 위험 무관 균일 |
| 3 | 위험 비례 검증. 사실엔 출처·재계산, 코드엔 테스트, 추론엔 반례. AI 주장 반박·수정 흔적 |
| 4 | 검증 파이프라인화(게이트 통과해야 채택). 틀린 산출 잡고 그 패턴을 prompt/hook 재발방지로 흡수 |

**자기기만** — "항상 검증"하지만 *그럴듯한 톤*에 설득돼 사실 검증 스킵. 코드는 검증해도 산문/수치는 무검증(최빈 누수).

## D3. 컨텍스트 엔지니어링 (Context Engineering)
**정의** — *무엇을 보여주고 무엇을 숨길지* 의도적 설계. 문구가 아니라 **컨텍스트 윈도우 정보 구성**.

| L | 시그널 |
|---|---|
| 0 | 컨텍스트 무투입. 파일 참조 없이 추상 질문 |
| 1 | 수동 복붙 덤프. 관련/무관 안 가림, 노이즈↑ |
| 2 | 선별 파일·발췌 제공. 단 세션 내내 누적·오염 방치 |
| 3 | 능동 관리. 관련 파일 주입, 무관해지면 새 세션/clear, 작업별 분리 |
| 4 | 영속화·재사용. CLAUDE.md/메모리/규칙파일에 도메인·제약 코드화해 자동 주입(예: 계층적 메모리 인덱스 구조) |

**자기기만** — 긴 프롬프트=좋은 컨텍스트 착각. 신호 대 잡음 낮으면 성능 깎임.

## D4. 루프·도구 오케스트레이션 (Loop & Tool Orchestration)
**정의** — AI를 단발 응답기가 아니라 *도구 쥔 실행 에이전트*로 운용.

| L | 시그널 |
|---|---|
| 0 | 채팅창만. 복붙으로 사람이 손수 연결(human glue) |
| 1 | 단일 도구 가끔. 결과는 사람이 다음 프롬프트로 옮김 |
| 2 | 에이전트 루프(Claude Code 등) read→edit→run. 단 매 사이클 사람 트리거 |
| 3 | 다중도구 자율 체인. 한 지시로 연쇄 실행, 실패 시 자가 재시도·분기 |
| 4 | 워크플로 오케스트레이션. 서브에이전트 분업·병렬·백그라운드·훅/크론. 도구를 새로 만들어(스크립트·MCP) 편입. 사람은 오케스트레이터 |

**자기기만** — "에이전트 도구 쓴다"를 고수준으로 착각. 매 스텝 hand-holding이면 L2(D1과 교차검증).

## D5. 모델 right-sizing·한계 운전 (Limits Navigation)
**정의** — 작업을 모델 *실제 능력 곡선*에 맞춰 배치·분해.

| L | 시그널 |
|---|---|
| 0 | 능력 무지. 못하는 걸 반복 요구하고 그대로 사용 |
| 1 | 실패 후 포기. 왜 틀렸는지 모름 |
| 2 | 재시도·리프레이즈(brute force). 분해 안 함 |
| 3 | 작업 분해·도구 이전. 산수→코드, 사실→검색, 큰 작업→청크로 재설계 |
| 4 | 모델·모드 포트폴리오. 난이도별 모델/추론깊이/도구 배분. 한계 사전 예측해 가드레일. "이건 모델 약하니 X로" 라우팅 |

**자기기만** — 못한 걸 "내 프롬프트 탓"으로만 (또는 전부 모델 탓). 경계를 모르니 같은 벽에 반복.

## D6. 반복 속도·폐기 비용 (Iteration Velocity & Disposability)
**정의** — 아이디어→산출→폐기/채택 사이클을 얼마나 빠르고 싸게. 핵심은 **틀린 산출을 미련 없이 버리는** 태도.

| L | 시그널 |
|---|---|
| 0 | 단발. 한 번 받아 그대로 |
| 1 | 손으로 수정, AI에 안 되돌림. 사이클이 사람 손에서 끝남 |
| 2 | 재요청하나 직렬·소량. 느린 왕복 |
| 3 | 빠른 재생성 루프. 안 맞으면 즉시 폐기·재생성, 손수정 최소 |
| 4 | 병렬 탐색 + 싼 폐기. 복수 후보 동시 생성·비교. 실패 브랜치 미련없이 버린 흔적 |

**자기기만** — "빠르게 반복"이지만 첫 산출 정착·손다듬음(=느린 직렬). 속도≠고침횟수.

## D7. 자산 복리화 (Compounding into Reusable Assets)
**정의** — 일회성 작업을 *재사용 자산*(프롬프트·스킬·훅·스크립트·규칙·메모리)으로 전환. 가장 강한 moat 시그널.

| L | 시그널 |
|---|---|
| 0 | 매번 무에서 시작. 자산 0 |
| 1 | 개인 스니펫 보관(수동 재사용) |
| 2 | 구조화 템플릿 라이브러리, 손으로 불러 씀 |
| 3 | 자동 주입 자산. CLAUDE.md·규칙·메모리·커스텀 커맨드/스킬 상시 편입. 새 작업이 기존 자산 위에서 출발 |
| 4 | 자산이 자산을 낳음+도구화. 훅·서브에이전트·MCP·스크립트로 수집·진단·자동화 위임(consume 넘어 build). 워크플로를 *제품화*(예: 진단 도구를 직접 빌드) |

**자기기만** — 파일 많음=자산화 착각. 다시 안 쓰면 죽은 문서. 진짜 시그널은 *후속 작업이 그 자산을 실제 참조·재사용한 흔적*.

## 메타 노트
- **consume vs build / originate vs recognize** = 별도 축 아니라 *각 축 L4 천장*. L4 도달의 공통 게이트로 "consume 넘어 build/originate 흔적" 요구.
- **단일 축 고득점 함정**: D4만 높고 D2 낮으면 "빠르게 틀린 것 양산". moat는 *프로파일 형태*로 — D2·D5·D7 동반 상승해야 진짜 해자. D1·D4만 높은 건 흉내 쉬워 해자 아님.
- **공통 자기기만**: 거의 모든 축에서 "*분량/빈도*를 *수준*으로 착각". rubric은 전부 *분량 아닌 구조·선택성·재사용*을 채점.
